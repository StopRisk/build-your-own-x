# Проверка инициализации DX-LR30-900M22SP(T0) — Arduino Mega 2560 + DX-PJ27-V1.2 (SPI, RadioLib)

Скетч: `src/main.cpp` (PlatformIO) или копия в `Check/Check.ino` для Arduino IDE
(папка скетча и файл .ino должны иметь одно имя; плата — "Arduino Mega 2560").
Зависимость: RadioLib 7.8.1.

## !!! Питание

У Mega 2560 на выводе **3V3 всего ~150 мА** (стабилизатор на плате). DX-LR30 в
передаче (+22 дБм) потребляет до 250–300 мА — **от вывода 3V3 Mega питать нельзя**
(будут зависания/сбросы при TX). Используйте внешний 3.3 В LDO (AMS1117-3.3,
MCP1700, TPS7A20…) с током ≥ 500 мА, **GND — общий с Mega**. Логика 5 В (Mega) /
3.3 В (SX1262) совместима напрямую, делители не нужны.

## Подключение одного модуля (DX-PJ27-V1.2 -> Mega 2560)

| Контакт платы | Пин Mega | Назначение |
|---|---|---|
| SCK       | 52 | SPI SCK (аппаратный SPI Mega) |
| MOSI      | 51 | SPI MOSI |
| MISO (DI01) | 50 | SPI MISO (на плате DI01 = линия данных, не DIO!) |
| NSS       | 10 | SPI CS (он же аппаратный SS) |
| NRST      | 9  | сброс (активный LOW) |
| DI02/BUSY | 8  | сигнал «занят» SX1262 (RadioLib ждёт сам) |
| DIO1      | 2  | IRQ: TX_DONE / RX_DONE / CAD_DONE (обязателен! int0 Mega) |
| RXEN      | 6  | ВЫБОР ПРИЁМА внешнего PA/антенного переключателя (управляет Mega) |
| TXEN      | 7  | ВЫБОР ПЕРЕДАЧИ внешнего PA/антенного переключателя (управляет Mega) |
| VCC/GND   | внешний 3.3 В ≥ 500 мА / общий GND | обязательна антенна |

RXEN/TXEN — это НЕ UART. У SX1262/DX-PJ27 всё управление идёт по SPI, а
приёмопередающий тракт (PA / RxTx-switch) выбирается двумя GPIO-линиями RXEN/TXEN.
Скетч подключает их через `radio.setRfSwitchPins(RXEN, TXEN)` — RadioLib сам
поднимает TXEN на время передачи и RXEN на время приёма, опускает обе в LOW в idle.

## Второй модуль на той же Mega

Раскомментируйте `#define USE_TWO_MODULES` (или соберите окружение
`megaATmega2560_two`). Два модуля вешаются на ОБЩУЮ SPI-шину:

* SCK/MOSI/MISO — параллельно к обоим адаптерам (те же пины 52/51/50);
* уникальные пины модуля B: NSS=30, NRST=31, BUSY=32, DIO1=33, RXEN=4, TXEN=5;
* отдельные UART TX/RX для второго модуля НЕ нужны — их здесь нет в принципе
  (интерфейс модуля — SPI; RXEN/TXEN — GPIO управления антенным переключателем,
  для B используются свои пины 4/5).

Особенность Mega: аппаратных прерываний мало, поэтому обработчик `setDio1Action()`
(int0, pin 2) назначен на DIO1 модуля A, а DIO1 модуля B (pin 33) в тесте T5a
опрашивается (polling уровня + флаги чипа). Для ping-pong обмена этого достаточно.

Радиообмен между модулями проверяется тестами T5a (событие на DIO1) и
T5b (ping-pong). Оба NSS перед началом работы принудительно HIGH, весь низкоуровневый
SPI-обмен идёт в отдельных транзакциях (`beginTransaction/endTransaction`) — второй
модуль не подслушивает шину.

## Тесты в setup()

T0 грубая проверка SPI → T1 begin() → T2 конфигурация LoRa (+22 дБм, CRC, лимит тока)
→ T3 калибровки RC/PLL/image + SetPaConfig → T4 контрольный TX → T5 CAD-сканирование
→ T5a IRQ на DIO1 (2 мод.) → T5b ping-pong (2 мод.) → T6 sleep/wake.
В loop(): каждые 5 с мониторинг эфира (или продолжение обмена) + состояние RXEN/TXEN/BUSY/DIO1.

## Сборка

```
pio run -e megaATmega2560              # один модуль
pio run -e megaATmega2560_two          # два модуля (ping-pong)
pio run -e megaATmega2560 -t upload --upload-port COMxx
pio device monitor                     # 115200
```

Оба варианта компилируются без ошибок (проверено): RAM ~3.5 КБ (72% в варианте
двух модулей — учтите это при расширении), Flash ~50 КБ из 256 КБ.
